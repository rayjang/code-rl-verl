## Hypotheses and decisions

* **smoke_rl_v1** (parent ): verl 0.9 + Qwen1.5-MoE LoRA + RUSCA agent loop + hierarchical sampler + verifier reward run end-to-end for 3 steps on 64 rows — changed: `n/a (system smoke)` → **reject**: attempt 4 (4 GPUs, bf16 model_dtype): rollout + verifier (64 samples, 0.6 s/verify) + update OK; crashed in trainer metrics: agent loop dropped TokenOutput.extra_fields (min/max_global_steps) -> fixed
* **exp_D000_baseline** (parent exp_D000_baseline):  — changed: `` → **keep**: baseline
* **exp_D001_f2p_binary** (parent exp_D000_baseline): All-or-nothing F2P removes partial signal: lower held-out solve rate than the baseline power law — changed: `reward.f2p_mode=binary` → **keep**: val_resolved 0.1300 > best 0.12625
* **exp_D002_f2p_linear** (parent exp_D000_baseline): Linear partial credit (half=0.5) learns faster early but rewards easy-test picking — changed: `reward.f2p_mode=linear` → **keep**: val_resolved 0.1437 > best 0.13
* **exp_D003_f2p_ladder** (parent exp_D000_baseline): Threshold ladder (partial/mostly/complete) gives coarse but stable credit — changed: `reward.f2p_mode=ladder` → **reject**: cancelled at model switch (Qwen1.5-MoE -> Qwen3-30B-A3B for long context); partial run kept
* **exp_D004_p2p_strong** (parent exp_D000_baseline): Strong linear P2P penalty (1/30 costs 3.3%) is noisier and lowers solve rate — changed: `reward.p2p_mode=linear,p2p_max=1.0` → **reject**: run failed or no validation metric
* **exp_D005_p2p_tolerant** (parent exp_D000_baseline): Two free regressions (flaky allowance) keeps signal without raising regression rate — changed: `reward.p2p_mode=tolerance,p2p_tolerance=2` → **reject**: run failed or no validation metric
* **exp_D006_rule_only** (parent exp_D000_baseline): Rule-only 0/1 reward (no format/partial bands) learns slower on this model — changed: `reward=rule_only` → **reject**: run failed or no validation metric
* **exp_D007_rubric_heavy** (parent exp_D000_baseline): Checkable-rubric credit (0.4, never decays) improves format/apply rate but not solve rate — changed: `reward.rubric_weight=0.4` → **reject**: run failed or no validation metric
* **exp_D008_rusca** (parent exp_D000_baseline): RUSCA (scaffold + rubric credit decaying to rule-only) beats both rubric-heavy and rule-only — changed: `reward.rubric_weight=0.2 with RUSCA stage decay` → **reject**: run failed or no validation metric
* **exp_D009_no_scaffold** (parent exp_D000_baseline): Without prompt scaffolding (RUSCA disabled) early exploration is worse — changed: `rollout.custom.rusca.enable=False` → **reject**: run failed or no validation metric
* **exp_D010_additive_nogate** (parent exp_D000_baseline): Non-gating additive reward (format/rubric credit even when apply fails) inflates train reward without solve-rate gains — changed: `reward.mode=additive,gating=false` → **reject**: run failed or no validation metric
* **exp_D011_ddca** (parent exp_D000_baseline): DDCA length advantage shortens correct responses without hurting solve rate — changed: `algorithm.adv_estimator=grpo_ddca (beta 0.3)` → **reject**: run failed or no validation metric
* **exp_D012_parser_baseline** (parent exp_D000_baseline): The baseline 6-stage cascade (fuzz apply, no validation) inflates apply rate but rewards malformed patches — changed: `verifier.parser=baseline,apply_mode=fuzz` → **reject**: run failed or no validation metric
* **stageD_qwen15_note** (parent nan): nan — changed: `nan` → **nan**: nan
* **exp_Q000_baseline** (parent exp_Q000_baseline):  — changed: `` → **keep**: baseline
